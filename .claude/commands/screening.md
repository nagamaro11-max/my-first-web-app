# DUKE式新高値ブレイク投資術スクリーニング（J-Quants API版）

本日の日本株市場クローズ後のデータを使って、DUKE氏の「新高値ブレイク投資術」に基づくスクリーニングを実施し、候補銘柄リストを作成してください。

データ取得には **J-Quants API v2**（`https://api.jquants.com/v2`）を使用する。

---

## J-Quants API 認証・データ取得手順

### 認証フロー

J-Quants APIの認証情報は環境変数から取得する:
- `JQUANTS_MAIL_ADDRESS`: 登録メールアドレス
- `JQUANTS_PASSWORD`: パスワード
- `JQUANTS_REFRESH_TOKEN`: リフレッシュトークン（任意。設定済みなら再ログイン不要）

認証は以下の2段階で行う:

**Step A: リフレッシュトークン取得**（`JQUANTS_REFRESH_TOKEN` が未設定 or 期限切れの場合）
```
POST https://api.jquants.com/v2/token/auth_user
Content-Type: application/json
Body: {"mailaddress": "<JQUANTS_MAIL_ADDRESS>", "password": "<JQUANTS_PASSWORD>"}
→ レスポンス: {"refreshToken": "..."}  （有効期限: 1週間）
```

**Step B: IDトークン取得**（全データリクエストの前に必要）
```
POST https://api.jquants.com/v2/token/auth_refresh?refreshtoken=<refreshToken>
→ レスポンス: {"idToken": "..."}  （有効期限: 24時間）
```

以後すべてのAPIリクエストに `Authorization: Bearer <idToken>` ヘッダーを付与する。

### 重要な仕様

- **銘柄コード**: J-Quantsは5桁コード（4桁TSEコード + 末尾"0"）。例: トヨタ = `72030`、ソニー = `67580`
- **日付形式**: `YYYY-MM-DD`
- **ページネーション**: レスポンスに `pagination_key` がある場合、次のリクエストに `pagination_key=<値>` を付与して全データ取得すること
- **レート制限**: Freeプランは約12リクエスト/分。適切にウェイトを入れること

## データ取得に使用するエンドポイント

### 1. 上場銘柄一覧（マスターデータ）
```
GET /listed/info
→ セクター分類（Sector17Code/Sector33Code）、市場区分（MarketCode）、銘柄名を取得
```
レスポンス例:
```json
{
  "info": [{
    "Code": "86970", "CompanyName": "日本取引所グループ",
    "Sector17Code": "16", "Sector17CodeName": "金融（除く銀行）",
    "Sector33Code": "7200", "Sector33CodeName": "その他金融業",
    "MarketCode": "0111", "MarketCodeName": "プライム",
    "ScaleCategory": "TOPIX Large70"
  }]
}
```

### 2. 株価四本値（日次OHLCV）
```
GET /prices/daily_quotes?code=<5桁コード>&from=<YYYY-MM-DD>&to=<YYYY-MM-DD>
GET /prices/daily_quotes?date=<YYYY-MM-DD>  ← 全銘柄の当日データ
```
レスポンス例:
```json
{
  "daily_quotes": [{
    "Date": "2026-03-29", "Code": "86970",
    "Open": 1802.0, "High": 1814.0, "Low": 1785.5, "Close": 1808.5,

    "AdjustmentClose": 1808.5, "AdjustmentVolume": 1563200,
    "AdjustmentFactor": 1.0
  }]
}
```

### 3. 財務情報（決算データ）
```
GET /fins/statements?code=<5桁コード>
```
レスポンス例:
```json
{
  "statements": [{
    "DisclosedDate": "2026-02-14", "LocalCode": "86970",
    "TypeOfDocument": "1QFinancialStatements_Consolidated_IFRS",
    "NetSales": "50000000000", "OperatingProfit": "10000000000",
```

### 4. TOPIX指数（市場トレンド判定用）
```
GET /indices/topix?from=<YYYY-MM-DD>&to=<YYYY-MM-DD>
```
※ 日経平均はJ-Quantsでは提供されないため、TOPIXで市場トレンドを判定する

## DUKE式スクリーニング基準（全条件）

### ステップ1: 新高値銘柄の算出

J-Quants APIで年初来高値更新銘柄を自力算出する:

1. `GET /prices/daily_quotes?date=<本日>` で本日の全銘柄終値を取得（pagination_key で全ページ取得）
2. 各銘柄について `GET /prices/daily_quotes?code=<5桁コード>&from=<年初日付>&to=<前営業日>` で年初来の株価履歴を取得
3. 本日の高値（High）が年初来の過去最高値（max(High)）を上回っている銘柄を「年初来高値更新」と判定

**効率化のコツ:**
- まず本日の全銘柄データを一括取得（`date`パラメータ）
- 年初来データは対象銘柄ごとに`from`を当年1月第1営業日、`to`を前営業日に設定
- APIレート制限（Free: 12回/分）に注意し、リクエスト間に適切なウェイト（5秒程度）を入れる

### ステップ2: 市場規模フィルター

時価総額をJ-Quantsデータから算出する:
- **時価総額 = 本日終値（AdjustmentClose） × 発行済株式数**
- 発行済株式数は `GET /fins/statements?code=<コード>` の `NumberOfIssuedAndOutstandingSharesAtTheEndOfFiscalYearIncludingTreasuryStock` フィールドから取得
- **条件**: 時価総額 500億円以下（200億円以下が最優先）
- **上場年数**: `GET /listed/info` のListing日情報 または MarketCode / ScaleCategory から推定。10年以内を優先

### ステップ3: セクターフィルター

`GET /listed/info` の `Sector33Code` / `Sector33CodeName` を使って判定する。

**J-Quants Sector33 除外コード:**
| Sector33Code | セクター名 | 判定 |
|---|---|---|
| 0050 | 銀行業 | 除外 |
| 0100 | 保険業 | 除外 |
| 0150 | 電気・ガス業 | 除外 |
| 1050 | 鉱業 | 除外 |
| 0200 | 農林・水産業 | 除外 |
| 3150 | 海運業 | 除外 |
| 3200 | 倉庫・運輸関連業 | 除外 |
| 1100 | 石油・石炭製品 | 除外 |

**優先セクター:**
| Sector33Code | セクター名 | 判定 |
|---|---|---|
| 3700 | 情報・通信業 | 優先 |
| 3750 | サービス業 | 優先 |
| 3300 | 小売業 | 優先 |
| 0350 | 医薬品 | 優先（バイオ含む） |
| 3650 | その他製品 | 条件付き |

上記以外のセクターは個別判断（成長性があれば残す）。

### ステップ4: 業績成長フィルター

`GET /fins/statements?code=<5桁コード>` で直近の決算データを取得し、以下を算出:

- **売上高成長率**: `NetSales` を前年同期と比較。直近1〜2期で前年比 **+10%以上**
- **営業利益成長率**: `OperatingProfit` を前年同期と比較。直近1〜2期で前年比 **+20〜30%以上**
- **直近四半期**: `TypeOfCurrentPeriod`（1Q/2Q/3Q/FY）を確認し、前年同四半期と比較
  - 売上高 +10%以上、営業利益 +20%以上
- **営業利益率**: `OperatingProfit / NetSales` を2〜3四半期分計算し、拡大傾向を確認

**注意**: 財務データの値は文字列で返されることがある。数値変換時にnull/空文字をハンドリングすること。

### ステップ5: チャート・テクニカルフィルター

`GET /prices/daily_quotes?code=<5桁コード>&from=<6ヶ月前>&to=<本日>` で日足データを取得し、以下のパターンを数値的に判定:

1. **カップウィズハンドル**:
   - 過去3〜6ヶ月の `AdjustmentClose` でU字型を検出
   - 高値 → 底 → 回復 → 小幅調整 → ブレイクのパターン
   - 底の深さ: 高値から -12%〜-35% の範囲

2. **ボックス圏ブレイク**:
   - 過去4〜8週間の高値・安値のレンジ幅が5%以内
   - 本日の終値がレンジ上限を出来高増加と共に上抜け

3. **タイトなレンジからのブレイク**:
   - 直近2〜3週間の日足の高値-安値幅が3%以内に収束
   - 本日、上方ブレイク

### ステップ6: 出来高確認

日足データから算出:
- **25日平均出来高**: 過去25営業日の `AdjustmentVolume` の平均
- **出来高倍率**: 本日の `AdjustmentVolume` / 25日平均出来高
- **条件**: 出来高倍率 **1.5倍以上**

### ステップ7: 移動平均線の確認

週足データを日足から算出（各週の金曜終値、または最終営業日の終値を使用）:
- **13週移動平均線（13週MA）**: 過去13週分の週足終値の平均
- **26週移動平均線（26週MA）**: 過去26週分の週足終値の平均
- **条件1**: 本日終値 > 13週MA かつ 本日終値 > 26週MA
- **条件2**: 13週MA > 26週MA（ゴールデンクロス状態）

### ステップ8: 買い判断

スクリーニング通過銘柄について、以下の基準で「買い判断」を出力する:

**◎ 積極的に買い（強いシグナル）:**
- 全条件（ステップ2〜7）をクリア
- 本日の出来高が25日平均の1.5倍以上
- チャートがカップウィズハンドルまたはボックス圏ブレイクを形成
- TOPIX指数が上昇トレンド（直近の下落日が5営業日中3日以内）

**○ 試し買い（条件付き）:**
- 主要条件はクリアだが出来高倍率が1.5倍未満、またはチャートパターンが不明確
- エントリーは1/5ポジション（試し買い）のみ
- 追加買い条件: 試し買い後に株価が+5%以上継続上昇 かつ 出来高増加を確認してから追加1/5

**△ 様子見（見送り推奨）:**
- 業績・セクターは良好だが、株価が直近高値から大きく離れている（25日MAからの乖離率+20%超）
- 出来高が薄い（流動性リスク）
- TOPIXが弱い局面（直近10営業日中5日以上が下落）

**× 見送り:**
- 上記以外（業績・チャート・出来高のいずれかが不適合）

### ステップ9: 売り判断

保有銘柄・候補銘柄について、以下の売り基準を出力する:

**損切り（絶対条件）:**
- 買値から **-8〜10%** 下落: 即時全売却（理由を問わず）

**利確・撤退シグナル:**
- 買値から **+20〜25%** 到達: 保有の1/2〜全部を利確
- 週足で **26週移動平均線を明確に割り込む**: 全売却
- 出来高を伴わずに **高値圏で陰線が連続**（3日以上）: 警戒・縮小

**トレーリングストップ（利益を守る）:**
- 買値+20%到達後は「最高値から-10%」をストップラインとして引き上げ継続

## 実行手順

### Phase 0: 環境準備
1. 環境変数 `JQUANTS_MAIL_ADDRESS`、`JQUANTS_PASSWORD`（または `JQUANTS_REFRESH_TOKEN`）が設定されているか確認する
2. 未設定の場合はユーザーに入力を求める
3. J-Quants APIの認証フロー（Step A → Step B）を実行し、IDトークンを取得する

### Phase 1: 保有候補の更新
1. `/Users/komanagase/.claude/scheduled-tasks/duke-new-high-breakout-screening/holdings.md` を読み込む
2. 保有候補銘柄の現在値を `GET /prices/daily_quotes?code=<5桁コード>&date=<本日>` で取得
3. 損益率を算出し、売りシグナル（ステップ9）を判定する

### Phase 2: 新高値銘柄の特定
1. `GET /prices/daily_quotes?date=<本日>` で本日の全銘柄データを取得（全ページ）
2. 各銘柄について年初来高値を算出し、本日更新した銘柄を抽出
3. `GET /listed/info` で全銘柄のマスターデータを取得し、セクター情報を紐付け

### Phase 3: フィルタリング
1. ステップ2（市場規模）→ ステップ3（セクター）でまず絞り込み、候補数を削減
2. 残った候補に対してステップ4（業績）→ ステップ5（チャート）→ ステップ6（出来高）→ ステップ7（MA）を順次適用
3. 各フィルターの除外数を記録する

### Phase 4: 判定・出力
1. ステップ8の基準で買い判断（◎/○/△/×）を決定
2. TOPIX指数データ（`GET /indices/topix`）で市場トレンドを判定
3. 通過銘柄を「優先度: 高/中/低」で分類
4. 買い判断が◎または○の銘柄を holdings.md に追記（既存銘柄は更新のみ）
5. 売りシグナルが出た銘柄は holdings.md から撤退済みセクションへ移動

## 重要な注意事項

- **投資判断の最終確認は必ず自身で行うこと**（このスクリーニングは情報提供のみ）
- 「ビッグチェンジ」の有無は各社のIR情報・ニュースリリースも確認すること
- 市場全体が弱い時（TOPIXが直近10営業日中5日以上下落など）は候補銘柄のポジション縮小を検討
- エントリーは翌営業日以降、必ず1/5の試し買いから開始すること
- ストップロスは買値から-10%を厳守すること（◎銘柄も例外なし）
- 買い判断「◎」でもTOPIXが弱い時は「○（試し買い）」に格下げすること
- 利確後も株価が上昇継続する場合は残りポジションを保有してよい（トレーリングストップで管理）
- J-Quants Freeプランではデータ取得量に制限あり。銘柄数が多い場合はセクター・時価総額フィルターを先に適用して候補を絞ってからAPI呼び出しを行うこと
- APIレート制限（Free: 12回/分）を超えないよう、リクエスト間に5秒以上のウェイトを入れること
